## 🗺️ Demo Overview

This demo walks through **4 progressive security stages** for an AI chat workload hosted in Azure AI Foundry. Each stage increases network isolation and moves toward a production-hardened architecture.

| Stage | Name                     | Access Path                               | Key Point                               |
|-------|--------------------------|-------------------------------------------|-----------------------------------------|
| 1     | Direct AKS LB            | Jump VM → AKS Internal LB → App          | Show the app works internally           |
| 2     | APIM Public              | Internet → APIM (public) → AKS → Foundry | APIM as API gateway, public inbound     |
| 3     | APIM Private             | VNet only → APIM (internal) → AKS → Foundry | APIM locked to VNet                  |
| 4     | AFD + Private APIM       | Internet → AFD → APIM (internal) → AKS → Foundry | Full production pattern         |

---

## ⚙️ Pre-Demo Setup

### Deploy Infrastructure

```bash
azd env new demo
azd env set AZURE_LOCATION eastus2
azd env set VM_ADMIN_PASSWORD "YourStrongPassword123!"
azd env set APIM_MODE External     # Start with Stage 2
azd env set DEPLOY_AFD false       # Enable for Stage 4
azd up
```

> ⚠️ **Cost warning**: ~$800–900/month. Run `azd down --force --purge` after the demo.

## 🎬 Stage 1 — Direct AKS Internal LB Access

**Goal**: Show the .NET chat app is running and reachable from within the VNet.

1. Azure Portal → `vm-jump-{env}` → **Connect** → **Bastion**
2. From jump VM PowerShell:

```powershell
# Get credentials (run once)
az aks get-credentials --resource-group rg-pfaaa-demo --name aks-pfaaa-pfaaa-demo

# Get AKS internal LB IP
kubectl get service chat-app -n chat-app

# Test directly
Invoke-RestMethod -Method POST -Uri "http://<AKS-LB-IP>/chat/message" `
  -Body '{"message":"Hello!"}' -ContentType "application/json"
```

**Talking points**: Private API server, internal LB only visible inside VNet, Bastion required for VM access.

---

## 🎬 Stage 2 — APIM Public Access → AKS → Foundry

**Goal**: Demonstrate APIM as the API gateway with public inbound and private backend.

> Default deployment uses `APIM_MODE=External`

```bash
# From any internet-connected machine:
curl -X POST https://<APIM_GATEWAY_URL>/chat/message \
  -H "Content-Type: application/json" \
  -d '{"message":"What is Azure AI Foundry?"}'
```

**Talking points**: APIM is VNet-injected so backend calls to AKS never leave the VNet. App is publicly reachable via APIM but backend is fully private.

---

## 🎬 Stage 3 — Lock Down APIM to VNet Only

**Goal**: Close public APIM access — now only accessible from within the VNet.

```bash
azd env set APIM_MODE Internal
azd up
```

> ⏱️ APIM VNet mode change takes 15–45 minutes. Pre-deploy before the demo.

```bash
# From internet — should timeout:
curl -X POST https://<APIM_GATEWAY_URL>/chat/message --connect-timeout 10
```

**Talking points**: APIM has no public listener. Internal IP only resolvable inside VNet. Public attack surface eliminated.

---

## 🎬 Stage 4 — Azure Front Door Premium → Private APIM → AKS → Foundry

**Goal**: Show the full production pattern — public users reach the AI app via AFD private link.

```bash
azd env set DEPLOY_AFD true
azd up
```

After deployment, approve the AFD → APIM private link:
1. Azure Portal → **API Management** → **Networking** → **Private endpoint connections**
2. Approve the pending connection from Front Door

```bash
curl -X POST https://<AFD-ENDPOINT>.z01.azurefd.net/chat/message \
  -H "Content-Type: application/json" \
  -d '{"message":"Hello from the public internet via Front Door!"}'
```

**Talking points**: AFD uses private link to reach APIM — connection never traverses public internet. Full path: `User → AFD (public) → [private link] → APIM (VNet) → AKS LB (internal) → Pod → [private endpoint] → Foundry`.
