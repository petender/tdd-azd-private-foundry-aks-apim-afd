### Scenario Description

A progressive network-security demonstration showcasing how to harden an AI workload hosted in Azure AI Foundry. The agent code runs on a Private AKS cluster. Access is locked down in stages:

1. **Stage 1 – Direct AKS LB Access**: AKS internal load balancer exposes the app for initial demo purposes.
2. **Stage 2 – APIM Public**: APIM with public inbound and private backend to AKS. Direct APIM public access demonstrated.
3. **Stage 3 – APIM Private**: Public APIM access is closed; APIM moves to internal/VNet-only mode.
4. **Stage 4 – AFD + Private APIM**: Azure Front Door Premium added. Public users reach Foundry via AFD → APIM (private) → AKS → Azure AI Foundry.

The jump VM (no public IP, Bastion-only access) is used throughout to access private resources.

```
           │ Private Link

│ Stage 3+: Internal  │  Inbound: private (stages 3+)

           │ Internal VNet
           ▼
┌─────────────────────┐
│   AKS (Private)     │  Internal load balancer
│   .NET chat app     │  Pods: private subnet only
└──────────┬──────────┘
           │ Private endpoint / MI
           ▼
┌─────────────────────┐
│  Azure AI Foundry   │  Private hub + project
│  Chat Agent         │  No public network
└─────────────────────┘

Jump VM ──── Bastion ───── (all private resources)
```
